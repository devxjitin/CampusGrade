# CampusGrade

An assignment, GitHub-repository analysis and grading platform for one institution. Teachers publish assignments with rubrics, students link a repository, the platform snapshots and analyzes each commit and flags code similarity, and teachers grade and release results.

FastAPI + PostgreSQL backend, Next.js frontend, packaged as a Docker Compose stack. See [PRD.md](PRD.md) for requirements and architecture and [Sprint.md](Sprint.md) for the delivery plan.

## Requirements

- Docker Desktop (give it at least 4 CPUs, 8 GB RAM, 60 GB disk) with Compose v2
- PowerShell on Windows (the helper scripts have `.sh` twins where noted)
- For development outside Docker: Python 3.12 + [uv](https://docs.astral.sh/uv/) and Node 22

## Run it locally (development)

```powershell
scripts\init-secrets.ps1                 # once: generates ./secrets/*.txt (git-ignored)
docker compose -f compose.yaml -f compose.dev.yaml up --build
```

- App: http://localhost:3000 API: http://localhost:5001 (docs at `/docs`)
- Backend and frontend hot-reload from your working tree.
- Create the first admin (the password never touches a file):

```powershell
docker compose -f compose.yaml -f compose.dev.yaml run --rm -e BOOTSTRAP_ADMIN_EMAIL=you@example.com -e BOOTSTRAP_ADMIN_PASSWORD=<12+ chars> api python bootstrap_admin.py
```

## Run it like production

The production stack runs the same images CI publishes, behind Caddy with HTTPS, with hardened containers (non-root, read-only filesystems, dropped capabilities, resource limits).

```powershell
scripts\init-secrets.ps1                         # once
scripts\deploy.ps1 -Version v0.1.0               # pulls ghcr.io/devxjitin/campusgrade-{api,web}:v0.1.0
scripts\bootstrap-admin.ps1                      # once: first Super Admin
scripts\trust-caddy-ca.ps1                       # once: let your browser trust the local certificate
```

Open https://campusgrade.localhost. `deploy.ps1` runs the database migrations as a one-shot container, starts everything, smoke-tests `/api/ready` and the login page, and redeploys the previous version if anything fails. On Linux use `scripts/deploy.sh`.

To deploy locally built images instead of pulling:

```powershell
docker build -f backend/Dockerfile  -t ghcr.io/devxjitin/campusgrade-api:local-test .
docker build -f frontend/Dockerfile -t ghcr.io/devxjitin/campusgrade-web:local-test .
scripts\deploy.ps1 -Version local-test -NoPull
```

Pulling from GHCR needs `docker login ghcr.io` with a GitHub token that has `read:packages` (until the packages are made public).

### Configuration and secrets

- Non-secret settings: copy `.env.prod.example` to `.env.prod` (git-ignored) and edit (address, TLS mode, tuning).
- Secrets live only in `secrets/*.txt`, generated by `scripts\init-secrets.ps1` and mounted into containers at `/run/secrets`. Back this folder up: losing `secret_key` signs every user out and losing the database password locks you out of the data.
- To serve a real domain: set `SITE_ADDRESS`, `ALLOWED_ORIGINS`, `PRIVATE_S3_PUBLIC_ENDPOINT` and `CADDY_TLS=<your email>` in `.env.prod`; Caddy then obtains a Let's Encrypt certificate.

### Known limitations of running on Docker Desktop

- **Client IP:** Docker Desktop on Windows NATs published ports, so the API may see the Docker gateway address instead of the real browser address. Login rate limiting is then shared across clients. A Linux host does not have this problem.
- **Single machine:** if this PC is off, CampusGrade is off. Container restarts and reboots are handled by restart policies; hardware failure is not. PRD Appendix A describes moving to a server or AWS.

## Tests and checks

```powershell
$env:SECRET_KEY = "any-unique-value-of-at-least-32-characters"
uv sync
uv run pytest backend/tests          # DB-backed tests need Docker (testcontainers)
uv run mypy
cd frontend; npm ci; npm run lint; npx vitest run; npm run build
```

End-to-end browser tests: see [frontend/e2e/README.md](frontend/e2e/README.md). CI (`.github/workflows/ci.yml`) runs all of the above, builds and scans the images, starts the production stack and runs Playwright against it. Pushes to `main` and `v*.*.*` tags publish images to GHCR.

## Repository synchronization

Students link one public GitHub repository per assignment. After pushing commits, the student selects **Update repository**; CampusGrade archives and analyzes that exact commit and the teacher portal reflects it after processing. Teachers freeze the latest synchronized commit when evaluation starts; any still-live repositories freeze at the deadline. (Automatic polling and a dedicated worker arrive in Sprint 2.) Set a GitHub token with `scripts\init-secrets.ps1 -GithubToken <token>` to avoid GitHub's low anonymous rate limit.
