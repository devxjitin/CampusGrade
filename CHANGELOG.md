## Sprint 6 — Cookie session, CSRF, middleware

**Status: done, backend and frontend both completed and verified in this sandbox.** Unlike Sprints 4/5, the frontend half was done in the same session — cookie auth only pays off once the frontend actually uses cookies instead of localStorage, so there was no reason to split it across sessions this time.

- **Deviation from the plan, disclosed**: the plan sketches a new `canvasgrade_023` migration adding an `auth_sessions` table. This session found `services/session_service.py`'s existing `SqlRefreshToken`/`refresh_tokens` table (built in an earlier sprint for device-session revocation) is functionally identical under different column names (`ip_hash`~`ip_address`, `issued_at`~`created_at`, `last_seen_at`~`last_used_at`), and `user_routes.py` already has `GET /me/sessions`/`DELETE /me/sessions/{id}`/`POST /me/sessions/revoke-others` satisfying the plan's `/auth/sessions` ask under different names. Building a duplicate table would have been pure churn. **No new migration this sprint** — `alembic heads` unchanged at `canvasgrade_022`.
- **`config.py`**: `auth_cookie_mode: bool = True`, the plan's own rollback flag ("`AUTH_COOKIE_MODE=false` falls back to header auth. Keep the flag for two sprints").
- **`routes_fastapi/deps.py::get_bearer_token`**: reads the `campusgrade_access` httpOnly cookie first (when cookie mode is on), falls back to the `Authorization` header — a not-yet-updated client (there wasn't one, since the frontend was cut over in the same session, but the fallback still matters for e.g. direct API scripts) keeps working. Header support scheduled for removal in Sprint 10.
- **`routes_fastapi/auth_routes.py`**: `/login`/`/auth/refresh` now set `campusgrade_access` (httpOnly, 15 min), `campusgrade_refresh` (httpOnly, pre-existing), and `campusgrade_csrf` (readable by JS — the frontend echoes it back as `X-CSRF-Token`). `/logout` clears all three. New `GET /auth/me` returns the real `Principal` as JSON.
- **`core/csrf.py`, new**: `register_csrf_middleware` rejects any unsafe-method request (except the exempt `/login`/`/auth/refresh`) whose `X-CSRF-Token` header doesn't constant-time-match the `campusgrade_csrf` cookie.
- **Real bug caught before it shipped**: exceptions raised inside `@app.middleware("http")` don't reach `@app.exception_handler`s in FastAPI/Starlette — verified empirically with an isolated standalone test app, not assumed. Fixed by adding `core.errors.error_response(request, error)` (builds the same problem+json body directly) and having the CSRF middleware `return` it instead of `raise`ing.
- **Frontend, done this session**: `src/lib/session.ts` rewritten — no client-side JWT decode, no localStorage token/user storage, `fetchCurrentUser()` via `GET /auth/me` cached in memory, `SessionUser.role` widened to the real four-role union, new `isAdminRole()` helper. `src/lib/api.ts` — removed the `Authorization` header interceptor, added a `X-CSRF-Token` interceptor reading `campusgrade_csrf` from `document.cookie` on every mutating request, simplified the 401-retry logic (refresh once, retry, no token to store). New `src/middleware.ts` — coarse presence-only check on `campusgrade_access` for the `(dashboard)` route prefixes (`/admin`, `/assignments`, `/dashboard`, `/profile`, `/settings`); deliberately does not verify the JWT (that would require shipping the backend's `SECRET_KEY` to the browser). `AuthGate.tsx` now authenticates via `/auth/me`. Every `role === "admin"` call site across `frontend/src` (found via exhaustive grep — nav visibility, admin-only page gating; none were actually super-admin-exclusive server-side) updated to `isAdminRole()`. The one remaining `localStorage` usage in the frontend is an unrelated sidebar-collapsed preference.
- **Verified this session**: backend — `uv run pytest backend/tests` → `158 passed, 22 skipped` (was `154/15`). `uv run ruff check` clean on every new/touched file (`test_cookie_auth.py`, `test_security.py`, `auth_routes.py` added to CI's ruff list). `uv run mypy` → clean, 17 files. `alembic heads` → `canvasgrade_022 (head)`, unchanged. `import app` → **121 routes** (120 + `/auth/me`). Frontend — `npm install` (scratch dir, mounted drive too slow for a bare install), `npm run lint` clean, `npm run build` clean (all routes), `npx vitest run --passWithNoTests` → 14/14 passing. No new npm dependencies.
